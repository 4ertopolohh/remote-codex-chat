# RC-001 — app-server protocol notes

Checked against OpenAI's generated v2 protocol types and app-server source on 2026-10-04. The local PoC observed the deprecation notice on `codex-cli 0.160.0`.

## Resume and paginated history

- `thread/resume` accepts `threadId` and optional `excludeTurns`. With `excludeTurns: true`, the response contains thread metadata and live resume state without populating `thread.turns`; the server still resumes or rejoins the thread. OpenAI recommends this for paginated threads. [Resume parameter schema](https://github.com/openai/codex/blob/main/codex-rs/app-server-protocol/schema/typescript/v2/ThreadResumeParams.ts)
- For a paginated thread, resuming without `excludeTurns: true` triggers the observed `deprecationNotice`. This is a notice about full-history response hydration, not a failed resume. Likewise, `thread/read` with `includeTurns: true` triggers a related notice. [App-server implementation](https://github.com/openai/codex/blob/main/codex-rs/app-server/src/request_processors/thread_processor.rs)
- When a client needs history, request turn pages with `thread/turns/list` (`threadId`, optional opaque `cursor`, `limit`, `sortDirection`, `itemsView`), then request item pages with `thread/items/list` (`threadId`, optional `turnId`, `cursor`, `limit`, `sortDirection`). Follow each response's `nextCursor` until `null`. Turns default to descending order and summary item view; items default to ascending order. [Turn request](https://github.com/openai/codex/blob/main/codex-rs/app-server-protocol/schema/typescript/v2/ThreadTurnsListParams.ts), [turn response](https://github.com/openai/codex/blob/main/codex-rs/app-server-protocol/schema/typescript/v2/ThreadTurnsListResponse.ts), [item request](https://github.com/openai/codex/blob/main/codex-rs/app-server-protocol/schema/typescript/v2/ThreadItemsListParams.ts), [item response](https://github.com/openai/codex/blob/main/codex-rs/app-server-protocol/schema/typescript/v2/ThreadItemsListResponse.ts)

**Minimal PoC change:** send `{"threadId": id, "excludeTurns": true}` for `thread/resume`. The current CLI only uses the returned thread id before starting a new turn, so it does not need to page history. Add paginated reads when the application actually displays prior turns. This recommendation is an inference from the PoC's current use of the response and OpenAI's protocol guidance.

## Approval responses

Both `item/commandExecution/requestApproval` and `item/fileChange/requestApproval` expect a response object with a `decision` field. `accept` and `decline`, used by the PoC, are valid for both. `acceptForSession` and `cancel` are also supported; command approvals additionally define amendment variants. No approval response shape change is indicated. [Command response](https://github.com/openai/codex/blob/main/codex-rs/app-server-protocol/schema/typescript/v2/CommandExecutionRequestApprovalResponse.ts), [command decisions](https://github.com/openai/codex/blob/main/codex-rs/app-server-protocol/schema/typescript/v2/CommandExecutionApprovalDecision.ts), [file response](https://github.com/openai/codex/blob/main/codex-rs/app-server-protocol/schema/typescript/v2/FileChangeRequestApprovalResponse.ts), [file decisions](https://github.com/openai/codex/blob/main/codex-rs/app-server-protocol/schema/typescript/v2/FileChangeApprovalDecision.ts)
