# RC-003 — исследование чтения истории Codex app-server

Проверено 2026-10-04 по [официальной документации OpenAI Docs для Codex app-server](https://learn.chatgpt.com/docs/app-server) и типам, сгенерированным установленным `codex-cli 0.160.0` командой `codex app-server generate-ts --experimental --out <temp-dir>`. Типы описывают форму сообщений, а документация — ограничения исполнения. Версия на машине и публикация документации могут меняться независимо.

## Возможности и границы

| RPC | Подтверждённое поведение | Источник |
| --- | --- | --- |
| `thread/list` | Постраничный список сохранённых диалогов: `cursor`, `limit`, `sortKey`, `sortDirection`, фильтры `cwd`, `sourceKinds`, `archived`, `searchTerm` и др.; `nextCursor: null` означает конец. По умолчанию показываются неархивные интерактивные источники (`cli`, `vscode`), поэтому для диалогов приложения следует явно включать `appServer` в `sourceKinds`. | [Раздел List threads](https://learn.chatgpt.com/docs/app-server#list-threads-with-pagination--filters) |
| `thread/read` | Читает сохранённый диалог по `threadId` без загрузки в память и подписки на события. Без `includeTurns: true` возвращает метаданные; с ним — всю историю ходов. Для обычного просмотра списка и карточки достаточно чтения метаданных. | [Раздел Read a stored thread](https://learn.chatgpt.com/docs/app-server#read-a-stored-thread-without-resuming) |
| `thread/resume` | Загружает сохранённый диалог по `threadId`, позволяя продолжить его через `turn/start`. `excludeTurns: true` оставляет ответ без `thread.turns`; установленный PoC уже использует этот флаг. `initialTurnsPage` доступен в сгенерированном типе ответа/запроса установленной версии, но его необходимость для UI следует проверять отдельно. | [Раздел Start or resume a thread](https://learn.chatgpt.com/docs/app-server#start-or-resume-a-thread), [схема `ThreadResumeParams`](https://github.com/openai/codex/blob/main/codex-rs/app-server-protocol/schema/typescript/v2/ThreadResumeParams.ts) |
| `thread/turns/list` | Экспериментальный постраничный просмотр ходов без `resume`; по умолчанию от новых к старым. `itemsView` принимает `notLoaded`, `summary` (по умолчанию) или `full`. Ответ содержит `data`, `nextCursor`, `backwardsCursor`. | [Раздел List thread turns](https://learn.chatgpt.com/docs/app-server#list-thread-turns), [схема параметров](https://github.com/openai/codex/blob/main/codex-rs/app-server-protocol/schema/typescript/v2/ThreadTurnsListParams.ts) |
| `thread/items/list` | Экспериментальный постраничный просмотр сохранённых элементов без `resume`, по всему диалогу либо с фильтром `turnId`. По умолчанию элементы идут от старых к новым. Метод зависит от поддержки пагинации в активном хранилище; иначе сервер возвращает ошибку неподдерживаемого метода. Ответ содержит `data`, `nextCursor`, `backwardsCursor`. | [Раздел List thread turns](https://learn.chatgpt.com/docs/app-server#list-thread-turns), [схема параметров](https://github.com/openai/codex/blob/main/codex-rs/app-server-protocol/schema/typescript/v2/ThreadItemsListParams.ts) |

Экспериментальные методы и поля требуют `capabilities.experimentalApi: true` в `initialize`; без него сервер отклоняет их. Это относится к `thread/turns/list` и `thread/items/list`. Текущий мост вызывает `initialize` без `experimental_api`, поэтому транспорт отправляет значение `false` по умолчанию. Перед вызовом этих RPC мосту понадобится явно включить capability. [Experimental API opt-in](https://learn.chatgpt.com/docs/app-server#experimental-api-opt-in), [локальный транспорт](../../backend/codex_bridge/_transport.py), [вызов моста](../../backend/codex_bridge/bridge.py).

## Проверка установленного `codex-cli 0.160.0`

Официальная документация сейчас утверждает, что явное создание `historyMode: "paginated"` ещё отклоняется, а full-history reads, turn pagination и resume существующих paginated-записей пока не поддерживаются. Это **расходится с фактическим поведением установленной версии**: новый `thread/start` без `historyMode` вернул `historyMode: "paginated"`; после успешно завершённого хода `thread/read` с `includeTurns: true` вернул полный ход в том же и в новом процессе app-server. С включённым `experimentalApi: true` новый процесс успешно вернул один ход через `thread/turns/list` и два элемента через `thread/items/list`, оба раза с `nextCursor: null`. Проверка не охватывала явную передачу `historyMode` и `resume` этого конкретного диалога. [Раздел Start or resume a thread](https://learn.chatgpt.com/docs/app-server#start-or-resume-a-thread); локальный smoke: `codex-cli 0.160.0`, thread `01a107e5-b82a-79d0-ac8a-9981c929f074`, 2026-10-04.

Сгенерированная схема задаёт форму для восстановления видимого текста: `thread/read` возвращает `{thread}`; `thread.turns[]` содержит `id`, `items[]`, `itemsView`, `status`; пользовательский элемент имеет `{type: "userMessage", id, clientId, content: UserInput[]}`, где текстовый блок — `{type: "text", text, text_elements}`; ответ агента имеет `{type: "agentMessage", id, text, phase, memoryCitation, delivery, questions}`. В smoke пользовательский текст находился именно в `content[0].text`, а ответ — в `agentMessage.text`; `itemsView` нового процесса был `full`. Нужно учитывать, что `UserInput` также допускает изображения, аудио, skill и mention, поэтому нельзя предполагать, что каждый блок `content` — текстовый. [Thread](https://github.com/openai/codex/blob/main/codex-rs/app-server-protocol/schema/typescript/v2/Thread.ts), [Turn](https://github.com/openai/codex/blob/main/codex-rs/app-server-protocol/schema/typescript/v2/Turn.ts), [ThreadItem](https://github.com/openai/codex/blob/main/codex-rs/app-server-protocol/schema/typescript/v2/ThreadItem.ts), [UserInput](https://github.com/openai/codex/blob/main/codex-rs/app-server-protocol/schema/typescript/v2/UserInput.ts).

Для UI: получить список через `thread/list` с `sourceKinds: ["appServer"]`; `thread/read` без `includeTurns` использовать для метаданных, а страницы истории загружать через экспериментальные `thread/turns/list` и при необходимости `thread/items/list`. `thread/resume` вызывать для продолжения разговора. Это инженерный вывод из контракта и локального smoke, а не отдельное требование OpenAI Docs. [Список](https://learn.chatgpt.com/docs/app-server#list-threads-with-pagination--filters), [чтение](https://learn.chatgpt.com/docs/app-server#read-a-stored-thread-without-resuming), [продолжение](https://learn.chatgpt.com/docs/app-server#start-or-resume-a-thread).
