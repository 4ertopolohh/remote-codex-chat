# RC-010 runtime usage and rate limits

Checked 2026-10-05 against the installed `codex-cli 0.160.0` (`codex app-server generate-ts --experimental`) and OpenAI's first-party protocol. The [RC-010 issue](https://github.com/4ertopolohh/remote-codex-chat/issues/11) calls for actual runtime values, optional updates, and graceful failure.

## Supported reads and updates

- `account/rateLimits/read` is an app-server request with optional parameters. Its response has `rateLimits` (backward-compatible single snapshot), nullable `rateLimitsByLimitId` keyed by open limit IDs, nullable `ordinaryUsageAllowed`, `rateLimitResetCredits`, `accountId`, and `rateLimitUpsell`. `ordinaryUsageAllowed: null` is unavailable; clients must not infer permission or recovery from percentages or reset times. [OpenAI protocol response](https://github.com/openai/codex/blob/main/codex-rs/app-server-protocol/schema/typescript/v2/GetAccountRateLimitsResponse.ts), [request definition](https://github.com/openai/codex/blob/main/codex-rs/app-server-protocol/src/protocol/common.rs).
- A `RateLimitSnapshot` has nullable `limitId`, `limitName`, `primary`, `secondary`, and other account-related fields. A present window has `usedPercent` and nullable `windowDurationMins` and `resetsAt`; `resetsAt` is a Unix timestamp in seconds. The two windows are protocol slots, not a guarantee that either exists for every account or bucket. [Snapshot](https://github.com/openai/codex/blob/main/codex-rs/app-server-protocol/schema/typescript/v2/RateLimitSnapshot.ts), [window](https://github.com/openai/codex/blob/main/codex-rs/app-server-protocol/schema/typescript/v2/RateLimitWindow.ts).
- `account/rateLimits/updated` carries one `rateLimits` snapshot. The protocol explicitly calls it a sparse rolling update and directs clients to merge available values into the latest read or refetch. Nullable account metadata in an update does not clear previously observed data. [OpenAI notification type](https://github.com/openai/codex/blob/main/codex-rs/app-server-protocol/schema/typescript/v2/AccountRateLimitsUpdatedNotification.ts), [notification method](https://github.com/openai/codex/blob/main/codex-rs/app-server-protocol/src/protocol/common.rs). Refetching is the simpler safe option when bucket association or field semantics are uncertain; this is an implementation inference.
- Separate `account/usage/read` returns account token summary and optional daily buckets; with `threadId`, it may include estimated thread usage. `thread/tokenUsage/updated` reports turn/thread token usage, which is distinct from account rate-limit buckets. [Usage request](https://github.com/openai/codex/blob/main/codex-rs/app-server-protocol/schema/typescript/v2/GetAccountTokenUsageParams.ts), [response](https://github.com/openai/codex/blob/main/codex-rs/app-server-protocol/schema/typescript/v2/GetAccountTokenUsageResponse.ts), [turn notification](https://github.com/openai/codex/blob/main/codex-rs/app-server-protocol/schema/typescript/v2/ThreadTokenUsageUpdatedNotification.ts).

## Local runtime evidence

`codex --version` reported `codex-cli 0.160.0`; the executable was `the local Codex executable`. From `backend/`, `python -m uv run python -m poc.codex_app_server_poc limits` initialized `codex_vscode/0.160.0` and successfully read `account/rateLimits/read`. The probe parsed the reply locally and recorded only its shape: keys `accountId`, `ordinaryUsageAllowed`, `rateLimitResetCredits`, `rateLimitUpsell`, `rateLimits`, `rateLimitsByLimitId`; `ordinaryUsageAllowed: true`; two current bucket IDs, `base_model_inference` and `codex`; primary and secondary windows present in the compatibility snapshot; reset-credit count 1. Account ID, percentages, balances, and reset timestamps were intentionally omitted. This is a point-in-time observation for this account, not a fixed bucket catalog. The invocation uses the repository's [PoC client](../../backend/poc/codex_app_server_poc.py), which sends the actual RPC, and is consistent with the earlier [RC-001 observation](../poc/RC-001-codex-app-server.md).

## Reset action boundary

The installed schema contains `account/rateLimitResetCredit/consume` with an idempotency key and optional opaque credit ID, plus reset-credit availability/details in the read response. [Consume params](https://github.com/openai/codex/blob/main/codex-rs/app-server-protocol/schema/typescript/v2/ConsumeAccountRateLimitResetCreditParams.ts), [credit summary](https://github.com/openai/codex/blob/main/codex-rs/app-server-protocol/schema/typescript/v2/RateLimitResetCreditsSummary.ts). The read probe does not establish the account's permission to redeem any particular credit or the product policy for offering the action. No consume request was sent. For RC-010, a read-only surface meets the issue's conditional reset requirement without inventing reset behavior.
